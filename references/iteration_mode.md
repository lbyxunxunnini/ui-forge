# Iteration Mode (uif-iter)

## 触发条件

### 显式触发

用户输入 `uif-iter` 时进入。

### 隐式触发（需确认）

当检测到以下条件时，提示用户是否进入迭代模式：

1. 项目存在 `.ui-forge/projects/<project>.design_card.yaml`
2. design card 状态或 `.design-doc/README.md` 标记为"已完成"

提示格式：
```
[ui-forge] controller：检测到已完成项目
- 项目名称：（项目名）
- 上一版本：design-output/
- 已完成页面：（页面列表）
- 是否进入迭代模式？
  A. 是，进入迭代模式
  B. 否，使用标准模式重新设计
  推荐：A（迭代模式）
```

**必须用户明确确认才进入迭代模式，否则不触发。**

## 版本号确认

进入迭代模式后，必须先确认版本号：

```
[ui-forge] controller：迭代版本确认
- 当前版本：design-output/（初始版本）
- 本次迭代类型：
  A. patch（0.0.1 → 0.0.2）— 小修小补，不影响整体结构
  B. minor（0.0.2 → 0.1.0）— 新增功能/页面，有明显变化
  C. major（0.1.0 → 1.0.0）— 重大改版，风格/架构有本质变化
  D. 自定义版本号（请输入）
  推荐：根据变更范围判断
```

版本号格式：`vX.Y.Z`（语义化版本）
- 目录名：`design-output-vX.Y.Z/`
- 用户也可以直接输入自定义版本号（如 `v2.0`、`v1.0.0-beta`）

## 核心流程

```
用户触发迭代
  → 读取 design card + 记忆（.design-doc/README.md）
  → 确认项目状态：已有 design card 且标记为已完成
  → 确认迭代版本号（用户选择 patch/minor/major 或自定义）
  → 复制上一版 design-output/ → design-output-vX.Y.Z/
  → 完整需求分析（聚焦变更部分，L1-L4 按变更复杂度路由）
  → 完整 UI 设计（基于已有设计优化，非从零开始）
  → 视觉审查师评分（对比新旧版本，标注变更项）
  → 交付（更新 design-output-vX.Y.Z/ 内文件）
  → 生成 CHANGELOG.md（版本变更记录）
  → 生成 UI-CHANGELOG.md（逐页 UI 变更对比）
  → 更新 design card 状态
  → 自动退出
```

### 与标准流程的关系

迭代 = 标准流程 + 版本化输出 + 变更追踪。

- 需求分析师：必须走完整流程，但聚焦在"这次改什么"，不重复确认已锁定的设计决策
- UI设计师：基于已有设计优化，非从零开始；已锁定的 tokens 不得擅自修改
- 视觉审查师：评分时对比新旧版本，标注变更项
- 交付工程师：输出到版本化目录，生成变更记录

### 需求分析师迭代规则

1. **聚焦变更**：只追问本次迭代涉及的变更，不重复确认已锁定的设计决策
2. **继承已有**：已确认的功能、风格、平台等核心需求直接继承，除非用户明确要改
3. **变更范围确认**：必须明确本次迭代改哪些页面/功能，不改的不碰
4. **设计系统约束**：如果设计系统已锁定，修改 tokens 必须告知影响范围

### UI设计师迭代规则

1. **增量设计**：只修改变更涉及的页面/组件，不重新设计未变更的部分
2. **继承 tokens**：已锁定的 tokens 直接复用，如需修改必须走设计系统变更流程
3. **一致性保障**：修改后的页面必须与未修改的页面保持一致
4. **变更标注**：每个修改点必须标注"变更自上一版的什么"

### 视觉审查师迭代规则

1. **对比审查**：评分时对比新旧版本，不只看新版本
2. **变更聚焦**：重点审查变更部分，未变更部分只做一致性检查
3. **回归检查**：变更是否引入了新的视觉问题（布局错位、风格不一致等）

## 输出结构

```
design-output-vX.Y.Z/
├── index.html              # 更新后的画廊
├── pages/                  # 更新后的页面
├── style.css               # 更新后的样式
├── tokens.json             # 更新后的 tokens
├── icons/                  # 更新后的图标
├── components/             # 更新后的组件库
├── DESIGN-GUIDE.md         # 更新后的设计规范
├── REQUIREMENTS.md         # 更新后的交互需求
├── routing.json            # 更新后的路由表
├── consistency-report.md   # 更新后的一致性报告
├── CHANGELOG.md            # 版本变更记录（新增）
└── UI-CHANGELOG.md         # 逐页 UI 变更对比（新增）
```

## 文档同步更新规则（P0，违反即错误）

迭代交付时，所有文档型文件必须同步更新，不能只更新 HTML/CSS 而遗漏文档：

- **REQUIREMENTS.md** — 新增页面/组件的交互需求必须补充，变更的交互流程必须更新
- **DESIGN-GUIDE.md** — 新增/变更的组件规范必须补充，token 变更必须更新
- **routing.json** — 新增页面必须加入路由表，变更的跳转关系必须更新
- **consistency-report.md** — 重新执行跨页面一致性校验，更新报告
- **tokens.json** — 如有 token 变更必须更新
- **CHANGELOG.md** — 本次版本变更记录（新增）
- **UI-CHANGELOG.md** — 逐页 UI 变更对比（新增）

**交付工程师输出前必须逐项检查文档完整性，缺任何一项不得输出。**

## CHANGELOG.md 格式

```markdown
# Changelog

## vX.Y.Z (YYYY-MM-DD)

### 变更概述
- 本次迭代目标：（简述）
- 变更范围：（涉及哪些页面/功能）

### 新增
- 新增页面：XXX
- 新增功能：XXX

### 修改
- 修改页面：XXX — 变更内容
- 修改组件：XXX — 变更内容

### 修复
- 修复问题：XXX

### 设计系统变更
- 无变更 / 具体变更项
```

## UI-CHANGELOG.md 格式

```markdown
# UI 变更记录 - vX.Y.Z

## 逐页变更对比

### 消息列表页 (messages.html)
- 变更类型：样式优化
- 具体变更：
  - 标题字号：17px → 20px
  - 卡片圆角：12px → 16px
  - 新增：空状态插画
- 影响范围：无跨页面影响

### 骑行模式 (riding.html)
- 变更类型：功能新增
- 具体变更：
  - 新增：骑行计时器组件
  - 修改：指令按钮布局调整
- 影响范围：需同步更新 routing.json

## 未变更页面
- team.html — 无变更
- discover.html — 无变更
- profile.html — 无变更

## 设计系统变更
- tokens.json：无变更
- components/：无变更
```

## 记忆更新

迭代完成后，必须更新记忆：

1. 更新 `.design-doc/README.md`：记录新版本号、变更概述
2. 更新设计决策锁定记录：如有 tokens 变更，记录变更原因和影响范围
3. 更新 design card：如有规则变更，更新 design card

## 多版本管理

- 每个版本独立目录，不覆盖旧版本
- 最新版本的目录名记录在 `.design-doc/README.md` 中
- 用户可以随时查看任意版本
