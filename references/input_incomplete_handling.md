# 输入不完整处理

## 核心原则

1. **不要假装看懂设计图**：如果用户提供了设计图，但无法清晰理解，必须向用户确认
2. **不要自动补齐核心需求空白**：功能范围、整体风格、目标平台等核心需求不能自动补齐，必须向用户确认；非核心默认值（圆角、间距、阴影、字号等）可按 SKILL.md 规则 6 告知默认值
3. **先理解再执行**：在理解需求之前，不要急于执行
4. **视觉能力不可假装**：模型或环境不能读取图片/截图/画布时，必须进入 Visual Understanding Fallback，不能声称看过视觉细节

## 输入类型处理

### 文字描述

- 如果描述清晰，直接执行
- 如果描述模糊，向用户确认关键点
- 如果缺少必要信息，向用户补充

### 设计图

- 如果能清晰理解，直接执行
- 如果无法理解，向用户确认
- 如果部分理解，先确认不确定的部分

### 图片 / 截图 / 画布不可读

当模型或运行环境不支持视觉理解、图片加载失败、截图不可访问、画布无法读取时，启动 Visual Understanding Fallback：

1. 明确声明 `visual_evidence: unavailable`
2. 优先寻找可读替代信息：HTML/CSS、DOM、设计 token、组件列表、PRD、用户文字描述、文件名与目录结构
3. 如果替代信息足以收口 brief，可继续需求分析，但必须标注 `visual_evidence: text/code-only`
4. 如果任务是截图诊断、视觉还原或像素级审查，且没有替代信息，必须暂停并请求用户补充文字描述、标注图、页面结构或可读取文件
5. 后续视觉审查只能做结构/规范/DOM/CSS 证据审查；无法执行真实缩略/眯眼测试时，必须写明 `视觉未直接验证`

降级输出格式：

```text
[ui-forge] controller：视觉理解降级
- 原因：当前模型/环境无法读取视觉输入
- 可用证据：文字描述 / HTML/CSS / DOM / design card / 无
- 不可声明：已看过截图、像素细节、真实视觉效果
- 下一步：基于可读证据继续 / 请求补充文字描述 / 请求可读取文件
```

### PRD/需求文档

- 如果文档完整，直接执行
- 如果文档不完整，向用户补充缺失部分
- 如果有歧义，向用户确认

## 确认机制

### 确认时机

1. 需求理解后
2. 关键决策点
3. 方案确认前

### 确认格式

```
[ui-forge] 需求分析师：需要确认
- 确认点：（具体问题）
- 选项A：（选项描述）
- 选项B：（选项描述）
- 推荐：（推荐选项）
```

### 确认规则

1. 确认点必须具体，不能模糊
2. 必须给出选项，不能只问开放性问题
3. 必须给出推荐，不能只问用户
4. 用户确认后，才能继续执行

### 用户拒绝提供信息时的处理

当用户拒绝回答信息（如"随便你"、"你决定"、"我不想说"）时，先区分缺口类型：

1. **低风险视觉默认值**：可切换到 autonomous 模式，用推荐方案补齐并标注为 `auto_assumption`
2. **核心需求字段**（目标、范围、目标平台、主 CTA、页面骨架、核心交互、验收标准）：不得自动确认，只能给出推荐选项并请求用户确认
3. **用户持续拒绝确认核心字段**：保留为 `候选（未确认）`，只能输出方向草案或待确认 brief，不得进入完整设计或交付
4. **快速模式**：仅处理用户明确指定的局部修改；遇到核心歧义时中断确认

切换时输出：
```
[ui-forge] controller：用户未提供关键信息，切换到自动模式
- 缺失信息：（具体缺失内容）
- 自动采用：（仅限低风险视觉默认值）
- 待确认：（核心字段仍需用户确认）
- 标注：低风险项为 `auto_assumption`，核心字段为 `候选（未确认）`
```

## 不完整输入处理

### 缺少平台信息

```
[ui-forge] 需求分析师：需要确认
- 确认点：目标平台是什么？
- 选项A：iOS应用
- 选项B：Android应用
- 选项C：Web网页
- 选项D：响应式设计（多端适配）
- 推荐：根据描述推测，推荐选项X
```

### 缺少页面类型

```
[ui-forge] 需求分析师：需要确认
- 确认点：需要设计什么页面？
- 选项A：登录/注册页
- 选项B：首页/Dashboard
- 选项C：个人中心/设置页
- 选项D：其他页面（请描述）
- 推荐：根据描述推测，推荐选项X
```

### 缺少风格信息

```
[ui-forge] 需求分析师：需要确认
- 确认点：设计风格是什么？
- 选项A：简约风格（干净、留白）
- 选项B：现代风格（渐变、卡片）
- 选项C：商务风格（专业、稳重）
- 选项D：科技风格（深色、霓虹）
- 选项E：活泼风格（彩色、圆润）
- 推荐：根据描述推测，推荐选项X
```

### 缺少功能信息

```
[ui-forge] 需求分析师：需要确认
- 确认点：需要包含哪些功能？
- 功能列表：
  1. 表单输入（手机号、密码）
  2. 社交登录（微信、Apple）
  3. 动画效果（渐变背景）
  4. 其他功能（请补充）
- 推荐：根据描述推测，推荐功能X
```

## 返回机制

### 返回格式

```
[ui-forge] UI设计师：返回 需求分析师
- 缺失内容：按钮点击后的加载状态和成功/失败反馈
- 请补充：加载中的样式、成功后的跳转逻辑、失败时的提示方式
```

### 返回规则

1. 返回只允许向上游返回，不允许跨角色返回
2. 返回后，被返回角色必须响应，不允许忽略
3. 响应格式与返回格式相同，只是把"缺失内容"改为"补充内容"
4. 一轮任务最多返回 2 次。超过 2 次仍未解决，由决策权最高的角色拍板
