# 视觉质量门禁

## 触发条件

UI设计师输出设计方案后，自动触发视觉质量审查。

## 门禁流程

```
UI设计师输出设计方案
  → 视觉审查师评分（6维度，满分30）
  → 门禁判定
    → ≥24分：放行，进入交付
    → 20-23分：放行，标记需优化项
    → 15-19分：阻塞，返回UI设计师修改低分项
    → <15分：阻塞，触发重设计
```

## 评分维度

详见 [visual_reviewer.md](../roles/visual_reviewer.md)

| 维度 | 权重 | 最低要求 |
|------|------|----------|
| 视觉丰富度 | 1/6 | ≥2 分 |
| 信息层次 | 1/6 | ≥2 分 |
| 组件精致度 | 1/6 | ≥2 分 |
| 色彩节奏 | 1/6 | ≥2 分 |
| 功能闭环 | 1/6 | ≥3 分（核心功能必须闭环） |
| 文稿精度 | 1/6 | ≥2 分 |

## 门禁阈值

| 总分范围 | 百分比 | 处理 |
|----------|--------|------|
| ≥ 24 | 80%+ | 直接进入交付 |
| 20-23 | 67%-77% | 进入交付，标记需优化项 |
| 15-19 | 50%-63% | 阻塞，返回 UI设计师修改 |
| < 15 | <50% | 阻塞，触发重设计 |

## 单维度一票否决

即使总分 ≥24，如果任一维度 ≤1 分，仍需阻塞返回修改。

## 修改轮次限制

- 最多 2 轮修改
- 第 1 轮：视觉审查师指出必改项，UI设计师修改
- 第 2 轮：视觉审查师只验证修改项，如仍有问题则升级
- 第 3 轮仍不达标：升级为需求分析师决策（接受现状或重设计）

## 与交付阶段的关系

视觉质量门禁通过后，才允许进入交付阶段。交付工程师负责生成代码，不负责提升视觉质量。
