# 视觉质量门禁

## 触发条件

UI设计师输出设计方案后，自动触发视觉质量审查。

## 门禁流程

```
UI设计师输出设计方案
  → 视觉审查师评分（6维度，满分30）
  → 门禁判定
    → ≥24分：放行，进入用户确认
    → 20-23分：放行，标注需优化项，进入用户确认
    → 15-19分：阻塞，返回UI设计师修改低分项（最多2轮）
    → <15分：阻塞，触发重设计
  → 用户确认设计（带评分参考）
  → 交付
```

## 评分维度

详见 [visual_reviewer.md](../roles/visual_reviewer.md)

| 维度 | 权重 | 最低要求 |
|------|------|----------|
| 视觉丰富度 | 1/6 | ≥2 分 |
| 信息层次 | 1/6 | ≥3 分（首屏主焦点必须清楚） |
| 组件精致度 | 1/6 | ≥2 分 |
| 色彩节奏 | 1/6 | ≥2 分 |
| 功能闭环 | 1/6 | ≥3 分（核心功能必须闭环） |
| 文稿精度 | 1/6 | ≥2 分 |

## 门禁阈值

| 总分范围 | 百分比 | 处理 |
|----------|--------|------|
| ≥ 24 | 80%+ | 直接进入交付 |
| 20-23 | 67%-77% | 进入交付，标记需优化项 |
| 15-19 | 50%-63% | 阻塞，返回 UI设计师修改 |
| < 15 | <50% | 阻塞，触发重设计 |

## 单维度一票否决

即使总分 ≥24，如果任一维度 ≤1 分，仍需阻塞返回修改。

## 设备画布与安全区硬门禁

App/iOS 交付必须以 iPhone 15 为默认展示设备：

- 页面 viewport 和页面容器锁定为 393×852，`overflow-y: auto`
- `index.html` 画廊必须使用真机外壳，并包含 `.iphone-frame`、`.iphone-screen`、`.dynamic-island`、`.status-bar`、`.home-indicator`
- 顶部安全区按 59px 处理，有导航栏页面内容起点为 103px；登录等无导航页面顶部 padding 至少 59px
- Tab 栏底部安全 padding 为 34px；底部操作栏高度为 95px，不能压住 Home Indicator
- 任一页面内容与状态栏、灵动岛、底部栏或 Home Indicator 重叠时阻塞返回

## 视觉层级硬门禁

视觉审查必须执行缩略/眯眼测试：页面缩到 25% 后，仍应能判断主焦点、主内容、主 CTA 的优先级。

- 首屏没有唯一主焦点：`信息层次` 最高 2 分，不能直接放行
- 未声明 `focus_chain`，或声明后没有对应到字号、字重、色彩、间距、组件形态：`信息层次` 最高 2 分
- 主任务、主内容、主 CTA 同权重，用户第一眼不知道重点：阻塞返回 UI设计师
- 不同内容类型的卡片长得高度相同，导致信息扫读失败：`组件精致度` 最高 2 分

## 修改轮次限制

- 最多 2 轮修改
- 第 1 轮：视觉审查师指出必改项，UI设计师修改
- 第 2 轮：视觉审查师只验证修改项，如仍有问题则升级
- 第 3 轮仍不达标：升级为需求分析师决策（接受现状或重设计）

## 与交付阶段的关系

视觉质量门禁通过后，才允许进入交付阶段。交付工程师负责生成代码，不负责提升视觉质量。
