# Evaluation Rubric

用这份 rubric 评估 `ui-forge` 的输出是否真的比普通 UI prompt 更强。

## 评分维度

每项 0-2 分，总分 10 分。

### 1. 需求收口

- `0` 关键约束缺失，还在脑补
- `1` 收口了显性需求，隐性约束不足
- `2` 平台、流程、异常、状态、边界都已明确

**示例**：
- `0`：只说”设计一个登录页”，没问平台、风格、登录方式
- `1`：确认了平台和风格，但没问异常处理和输入验证
- `2`：确认了平台、风格、登录方式、异常处理、输入验证、边界情况

### 2. 结构判断

- `0` 直接堆组件
- `1` 有基本布局，但没有明确主次或首屏焦点
- `2` 有清晰的信息层级、唯一主焦点、`focus_chain` 和浏览路径

**示例**：
- `0`：所有内容平铺排列，无视觉分区
- `1`：有标题和内容分区，但所有元素同等权重
- `2`：主内容先进入视线，核心判断信息第二层出现，主操作按钮有明确落点，次要信息被弱化

**最低要求**：必须能说明首屏 `focus_chain`。如果页面缩到 25% 后看不出重点，结构判断最高只能给 `1`。

### 3. 视觉语言

- `0` 泛模板化，默认审美明显
- `1` 有风格选择，但一致性不足
- `2` 风格明确，type、space、surface、color 说同一种语言

**示例**：
- `0`：默认 Bootstrap 样式，无定制
- `1`：有自定义配色，但间距/圆角/阴影不一致
- `2`：配色/字体/间距/圆角/阴影形成统一的视觉语言

**最低要求**：必须有明确的设计风格定义（深色/浅色/运动/简约等），禁止”无风格”输出。

### 4. 交互完整性

- `0` 只覆盖静态态
- `1` 覆盖常见状态
- `2` 覆盖 focus、error、empty、loading、success、responsive

**示例**：
- `0`：只有默认展示态，无任何交互反馈
- `1`：按钮有 active 态，列表有点击效果
- `2`：输入框有 focus/error/success 态，有空状态插画，有 loading 动画，有响应式适配

**最低要求**：每个可交互元素至少覆盖 2 种状态（default + 1 种反馈态）。

### 5. 交付可用性

- `0` 只有概念，没有落地
- `1` 有部分落地材料
- `2` 有可直接交给前端或后续 LLM 的设计说明和产物结构

**示例**：
- `0`：只有文字描述，无代码/无规范文档
- `1`：有 HTML 但无 CSS 分离，有设计说明但无 token
- `2`：HTML/CSS 分离，有 tokens.json，有 DESIGN-GUIDE.md，有 REQUIREMENTS.md，图标独立导出

**最低要求**：必须产出 index.html + style.css + tokens.json + icons/ + DESIGN-GUIDE.md + REQUIREMENTS.md 六件套。

## 及格线

- `8/10`：可用于真实项目试跑
- `9/10`：可作为开源展示样例
- `< 8/10`：需要回到结构判断或交互完整性修正

## 视觉质量附加评估（独立于上述 10 分）

在上述 5 维度评分之外，视觉审查师还需按以下 6 维度评分（详见 [visual_reviewer.md](roles/visual_reviewer.md)）：

| 维度 | 满分 | 及格线 |
|------|------|--------|
| 视觉丰富度 | 5 | ≥3 |
| 信息层次 | 5 | ≥3 |
| 组件精致度 | 5 | ≥3 |
| 色彩节奏 | 5 | ≥3 |
| 功能闭环 | 5 | ≥3 |
| 文稿精度 | 5 | ≥3 |
| **总分** | **30** | **≥20** |

## Baseline 对比

评测时至少对比两组输出：

- 普通”帮我设计一个页面” prompt
- `ui-forge` 输出

观察差异时，优先看：

- 有没有先收口再设计
- 有没有解释为什么这样设计
- 有没有明确禁止项
- 有没有交互和状态层
- 有没有视觉丰富度（不只是文字列表）
- 有没有精确到逐元素的设计标注
