# Skill 可见性规则

## 可见性合同

对外输出不是展示格式问题，而是阶段执法的一部分。

### 仅允许

- 所有对外输出使用 `[ui-forge]` 前缀
- 明确标注当前角色
- 按阶段顺序逐角色输出
- 在当前阶段未闭环时，只输出当前角色，不提前切下游
- 在需要确认时显式暴露 `已确认 / 待确认 / auto_assumption`

### 明确禁止

- 跳过前面角色直接给结论
- 合并多个角色到一段输出
- 把推荐方案伪装成用户确认
- 自动补齐核心需求却不标注
- 看不懂输入却输出肯定句
- 用“完成了”掩盖“当前只是某阶段结束”

### 违规后强制动作

1. 立刻停止当前输出
2. 指出跳阶段、越权补齐或假完成点
3. 回退到对应角色和确认节点
4. 仅输出当前需要处理的问题

## 标准格式

```text
[ui-forge] 角色名：
- 决策/建议内容
- 原因/理由
```

## 阶段化输出规则

- 需求分析阶段：允许输出已知摘要、待确认问题、推荐选项
- UI设计阶段：允许输出当前工作单元的结构、组件、状态、分支方案
- 视觉审查阶段：允许输出评分、门禁结论、必改项
- 交付与验证阶段：允许输出文件、验证结果、未通过项

只要 `exit_permission != true`，都禁止输出“任务完成”。

## 追问格式

```text
[ui-forge] 需求分析师：第N轮追问
- 问题描述？
  A. 选项1（说明）
  B. 选项2（说明）
  C. 选项3（说明，可选）
  推荐：选项X（推荐理由）
```

```text
[ui-forge] UI设计师：第N步 - （步骤名称）
- 方案A：（方案描述）
- 方案B：（方案描述）
- 方案C：（方案描述，可选）
- 推荐：方案X（推荐理由）
- 请选择方案，我将继续追问该方案的设计细节
```
